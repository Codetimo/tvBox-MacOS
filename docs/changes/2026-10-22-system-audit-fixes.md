# 系统审查缺陷修复与 1.0.1 发布

## 原因

结合设计说明、代码和 2026-10-22 日志检查，发现直播列表误解析、收藏身份不稳定、详情误匹配、搜索覆盖及调度不足、格式判断遗漏，以及 Bridge 执行隔离、缓存和多窗口生命周期缺陷。本次使用三个子代理分工修复，再交叉审查并由主代理整合。

## 主要修改与决策

- 区分 IPTV 频道列表与 HLS 主/媒体清单；HLS 保留原频道名、播放地址和请求头。列表读取有大小/耗时上限，不全量下载直播视频；UTF-8 前缀跨字符截断及 UTF-16 BOM 有回归覆盖。
- 更新源时按地址复用原频道 ID；地址轮换只对两侧唯一的同名同组频道回退匹配，保留历史收藏。URL 去重只规范化协议、主机名，不改变路径及签名参数大小写。
- 明确不同的详情 ID 不允许按名称或唯一结果兜底；缺失 ID 的兼容仍保留。
- 目录、CMS、Spider 独立限流，完成即补入后续任务；普通 Spider 也参与搜索。CMS 详情按点击加载，保留认证参数及浏览器请求头。新增取消搜索入口，关闭窗口取消所属任务，已返回结果保留。
- 媒体路由使用最多 4 KiB 的响应内容探测，识别无后缀 HLS/MP4、HTML 等；公网 MP4 地址也探测 MKV。探测失败保留播放器尝试机会，不因 Range 不兼容阻断播放。请求头覆盖忽略大小写。
- SpiderService 由应用根持有，各窗口共享；并发启动合并为独立任务，取消调用者只取消等待，复用服务继续健康监控，过时启动响应不得恢复已停止服务。
- Bridge HTTP/health 与 Spider 业务执行分池；16 个执行线程、24 排队位置，同 URL 最多接纳 8 请求，20 秒返回超时。无法中断的任务在真正退出前占用配额，避免重试无限堆积；包初始化改为包级锁。
- Spider 缓存按 SHA-256 内容分目录；无 MD5 地址每 5 分钟按需重验证，扫码期间延后；不同 URL 的相同内容共享包/loader，原生库随内容版本更换路径。重验证失败明确报错，不静默使用旧包。并发落盘校验 SHA/CRC，异常清理暂存文件。
- Bridge 补充 request_id、站点类、接口、耗时、状态及异常类型日志；不输出凭据、URL 和第三方异常原文。非致命 Error、超时与响应写入竞态均关闭或完成连接。
- 更新 README 与 Bridge 文档；CI 新增 JDK 17/Android 35 Bridge 构建与回归任务。发布脚本每次重建并内嵌 APK，launcher 优先使用内嵌版本，避免旧运行时 APK 遮蔽修复；应用版本更新为 1.0.1。

## 风险与回滚

- Bridge 仍在同一个 Android 进程运行第三方包。JNI 进程崩溃及多个包同时永久卡死尚未实现进程级隔离；有界队列、响应超时不等于能强制终止 JNI。
- 全新内容版本缓存保留旧文件以保护正在使用的 native 库，本次未增加磁盘缓存淘汰机制。
- 旧应用备份：`dist/backups/system-audit-20261022-162500/`。退出新版后，可用对应 `dist-TVBoxMacOS.app` / `installed-TVBoxMacOS.app` 恢复两处部署。回滚旧 Bridge 时需要按旧源码重新构建 APK；旧应用不携带 APK，不应继续使用新版运行时 APK 冒充完整回滚。
- 本次保留之前未提交的 AGENTS.md 和播放页搜索跳转变更。源库及钥匙串未迁移或清空，测试未写入真实网盘凭据。
