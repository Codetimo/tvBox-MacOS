# Spider 详情业务错误与换站入口

## 原因与诊断

- 复现截图中的「一人之下第六季」：蜗牛搜索成功，但详情返回 HTTP 200、空 `list` 和 `msg=蜗牛影视未登录，请先到配置中心登录或填写 Cookie`。
- 盘迷同一搜索的前两条结果返回空 `list`，提示「没有解析到123网盘链接」。
- 客户端只校验列表与影片 ID，丢弃了详情中的业务错误，统一显示「站点未返回所选影片的详情」。本次实际响应排除了 ID 匹配导致截图错误的假设。

## 修改与决策

- 抽取可独立测试的 Spider 详情解析入口；空列表或匹配影片无线路时保留 `msg/message/error`，兼容已有的嵌套包装，忽略通用成功文案。
- 保持影片 ID 校验：明确返回另一影片的 ID 仍拒绝；有效详情不因附加提示而失败。
- 详情失败时展示本次搜索中其他站点的真实结果，由用户核对片名并选择后加载。没有自动换影片、伪造线路或放宽登录限制。
- 保留已有工作区修改；本次不修改 Bridge、网盘凭据或用户源库。

## 验证

- 定向 41 项测试通过，新增 6 项覆盖登录要求、缺失分享链接、嵌套错误、无错误空响应、错误 ID 和有效详情。
- `swift test`：139 项通过，0 失败；Matroska 集成测试执行通过，无跳过。
- 实际 Bridge 健康；蜡笔搜索、详情成功返回同一影片，夸克和百度 player 响应均得到可访问 URL。
- 两条真实媒体均返回 HTTP 206；夸克内容为 Matroska，百度为 MP4；使用已安装 FFmpeg 分别成功解码一帧。UC player 明确提示未配置 UC Cookie。
- `scripts/package_app.sh` 成功，签名验证通过，替换固定安装路径 `~/Applications/TVBoxMacOS.app`。
- 重启时等待旧 launcher 清理模拟器后再启动，确认新进程使用固定安装路径，Bridge `/health` 恢复 `ready=true`。
- `git diff --check` 通过。辅助功能接口把窗口返回为应用自身，无法读取详情弹窗控件，新增入口尚未完成真实界面点击验收。

## 边界与回滚

- 蜗牛仍需要用户自行完成独立站点登录；盘迷的 123 链接解析失败属于提供商返回结果，不能宣称已经恢复这两个站点的播放。
- 媒体探测与解码不等同于最终应用窗口的完整播放验收。
- 回滚只撤销本次详情解析、错误提示和其他站点入口的差异，不覆盖工作区此前已有改动。诊断原始响应、播放 URL 和帧保存在仓库外，不提交凭据或签名地址。
