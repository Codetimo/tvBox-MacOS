# 工程审查问题修复

## 原因与范围

根据上一轮代码审查，由三个 agent 分工修复 Bridge、源身份/网络读取、影片业务/存储，再交叉审查并整合。保留当前工作区原有未提交改动；本次没有提交、打包部署或修改真实源库、收藏和网盘凭据。

## 主要修改与决策

- **Bridge 调度与恢复**：16 个业务线程，同 URL 最多接纳 8 个请求、同时执行 2 个。其余请求进入总量 24 的待调度队列，不占线程等待包锁。20 秒总时限包含排队；超时取消同包待执行请求并熔断 30 秒。已执行任务直到真正退出才释放名额，超时后 5 秒仍未退出则 health 报告 `ready=false/restartRequired=true`。launcher 识别该标记后 force-stop 整个 Bridge 进程，并维持 5 分钟最多 3 次恢复预算。
- **缓存生命周期**：仅新 Android 进程加载包之前，清理到最近使用的 8 个版本/512 MiB；同时回收旧格式包、孤立优化目录和暂存文件。运行期限制 16 版本，并按 1 GiB 下载准入预算与每次 256 MiB 预留检查空间，优化 DEX 归入内容版本目录。临时并发预留压力最多等 5 秒，返回繁忙而非触发重启；无正在进行的预留且容量不足时才请求恢复。会话包别名上限 256，累计 engine 构造上限 512。运行中不删除 native 文件；ART 实际优化文件大小由 Android 决定，准入预留不是文件系统磁盘配额。
- **站点与影片身份**：正常订阅使用已保存的源 UUID + 唯一站点 key 生成身份，API/ext/凭据轮换不改变主键。无订阅上下文时使用配置摘要，非规范重复 key 额外使用配置指纹。影片 ID 带站点身份，搜索去重和收藏不再合并不同订阅的同 ID 影片。同名站点的筛选、状态与结果计数也改用身份，原站点名继续展示。
- **导入与下载**：本地 JSON 改为异步读取并复用远程导入的直播列表展开流程。`BoundedResponseReader` 对实际响应字节与整个请求耗时设限，覆盖配置、CMS、Spider 响应和直播列表探测；直播仍在响应头/512/4096 字节处提前识别媒体并取消下载。取消导入不得返回半展开快照。目录失效时推进 generation，旧请求不能重新填入过期缓存。
- **收藏与播放调用链**：新增 `MovieApplicationService` 统一搜索、详情和播放解析的 `SpiderService.ensureReady()` 前置条件。`MovieDetailModel` 每次打开刷新详情，失败保留旧线路并说明状态；刷新期间禁止播放旧快照。收藏卡片直接选集也先刷新，按线路名与剧集名唯一匹配新地址，歧义时要求重新选择。详情重试纳入 SwiftUI `.task(id:)` 生命周期，关闭/切站取消后不得迟到写回收藏。旧启动任务的取消只停止自己的 generation。
- **职责与后台存储**：站源业务、详情状态及搜索站点状态分别抽离，逐步缩小 View 职责。`SourceLibraryRepository` 在 actor 上执行完整源库事务，UI 保持稳定实例；修复快照使用条件写回，防止删除后的源被后台修复复活。收藏的初始读取、编码及原子写入移到独立 actor，通过串行任务链处理快速连续操作，只在成功落盘后发布 UI 状态。读写期间禁用收藏按钮，文件损坏或写入失败保留原文件和已发布状态。
- **CI**：macOS 测试任务先运行固定版本与 SHA-256 校验的 FFmpeg 准备脚本，检查可执行文件；若 XCTest 报告跳过测试则 CI 失败，避免媒体集成测试静默缺席。

## 边界与回滚

- 尚未实现每个 Spider 独立进程；JNI 崩溃仍可能影响整个 Bridge，恢复会中断其他正在执行的站点。线程调度、熔断和有界进程恢复不能宣称永久消除第三方故障。
- 旧收藏没有订阅 UUID。仅在旧 ID、来源名及 Spider 配置一致时兼容匹配；多个历史订阅完全相同时，原数据无法恢复唯一归属，不做无歧义全量迁移声明。非规范重复 key 的配置指纹随配置变化可能改变身份。
- 设备验证使用受控源和测试媒体。真实供应方搜索/详情/播放、手机扫码以及新版界面人工操作没有重新验收，不能用测试通过替代供应方可用性声明。
- 本次未部署应用，真实用户数据尚未迁移。若需回退，以本次代码差异为单位撤销，避免重置原有工作；未来启用 v2 影片身份后，回退旧客户端还需处理收藏 ID 兼容。
